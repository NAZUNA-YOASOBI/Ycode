# 软件工程专业推免项目：构建编程智能体

本文档根据原始题目文件 [推免考核题目学生版.pdf](./推免考核题目学生版.pdf) 整理。“题目”至“面试环节”完整整理了 PDF 中的任务定义、规则、提交要求和面试要求；“项目实现原则”是项目负责人补充的强制要求。如需核对题目原始表述，以该 PDF 为准。

## 题目

个人独立设计并实现一个编程智能体（coding agent）：它通过与大语言模型交互，能自主地读写文件、执行命令，完成你交给它的编程任务，类似一个简化的 Claude Code、Codex、OpenCode、DeepSeek Harness 等。

功能繁简不限，可以很简单，也可以做得完善。不允许在现成 agent 产品上封装界面，也不得使用任何 agent 框架或 SDK，包括 LangChain、LlamaIndex、OpenAI Agents SDK、Claude Agent SDK、AutoGen、CrewAI 等。

允许使用以下能力：

- 模型厂商的 API 客户端库；
- OpenAI 兼容网关；
- 模型原生的 tool calling 接口。

不得依赖 API 服务端托管的代码执行或文件工具，例如 Code Interpreter、Files API。

重要逻辑需自行编写，包括但不限于：

- 对话历史与上下文管理；
- 工具的定义与本地执行；
- 模型输出的解析；
- 循环终止条件；
- 错误处理。

## 规则

1. 截止时间：2026 年 9 月 2 日 24:00，北京时间，即 9 月 3 日 0 点。
2. 允许并鼓励使用任何 AI 工具辅助开发，但须对项目中的每一处设计负责。
3. agent 运行时调用的模型不限，编程语言不限。
4. API key 等凭据一律通过环境变量或未入库的配置文件提供，不得出现在仓库、`README.txt` 或视频中；若曾误提交，请立即作废更换。

## 提交物

提交物共三项。

### 1. Git 仓库

- 必须是题目发布后新建的公开仓库，GitHub、Gitee 均可。
- 必须保留完整提交历史，不得压缩或改写已经推送的历史。
- 截止时间后不得再向仓库推送新提交。
- 评委会将结合提交时间与提交内容了解开发过程。
- Git 仓库地址必须写在提交的 `README.txt` 中。

### 2. README.txt

`README.txt` 限 1000 汉字以内，内容包括：

- Git 仓库地址；
- 如何运行；
- 特色功能说明；
- 其他想说明的内容（如有）。

### 3. 视频

- 时长在 2 分钟以内。
- 演示 agent 完成一个真实编程任务的过程。
- 简要讲解功能实现。
- 允许剪辑与加速播放。
- 使用 MP4 格式。
- 文件大小不超过 200 MB。

### 最终压缩包与提交方式

- 提交内容仅包含一个使用本人姓名命名的 ZIP 文件，文件名为“本人姓名.zip”。
- ZIP 文件内包含 `README.txt` 和视频文件。
- 提交地址：[南京大学表单](https://table.nju.edu.cn/dtable/forms/283d6c7d-475a-4f41-8baf-d3f45966ef2d/)。
- 可以重复提交，以最后一次提交为准。

## 面试环节

1. 现场播放视频。
2. 简单介绍设计方案。
3. 回答评委提问。

提问重点关注：

- 是否理解 agent 为什么这样运转；
- 是否能为设计决策给出辩护。

## 项目实现原则（用户补充）

1. 本项目是用于考核演示的最小 coding agent，不按完整产品建设，只实现题目要求的核心功能和必要流程。
2. 所有代码、文档和配置都必须简洁、清楚。可读性第一，核心功能正确性第二；两者不冲突时必须同时保证。
3. 只处理真实可达且会影响核心流程或演示结果的错误，不加入推测性的防御逻辑、兼容层、回退层或抽象层。
4. 不添加与关键逻辑无关、不影响题目完成的代码、文件、依赖、配置或说明。每一项内容都必须能说明其存在的必要性。
5. 文件数量尽可能少，相同职责的内容尽量放在同一文件中，不创建无意义的包装层、跳转层或胶水文件。
6. 目录分类必须有实际职责依据并保持浅层结构；既不把所有文件堆在根目录，也不拆分大量细碎目录。
7. Git 历史必须简洁、清楚。只在重要修改形成逻辑完整的阶段结果时执行 `git add` 和 `git commit`，不为零碎调整频繁提交；每个提交应当主题明确、便于评委理解开发过程。
8. GitHub 评审者应当能够快速找到项目入口，并看懂 agent 核心循环、工具执行、上下文管理和终止逻辑。
